# Git 対応

Git の表示と操作には、PATH 上の `git` コマンドを使う。Scarlet と Git がインストールされていない環境では
Git 機能を無効にし、Git ビューに理由を表示する。gix による代替実装は持たない。
Scarlet での再対応は、Git コマンドの移植後に行う。

## 表示と操作

- ステータスバーにブランチ名と変更数、エクスプローラーにファイルとフォルダの変更マークを出す。
  detached HEAD と、まだコミットのないブランチも表示する。
- Git ビューはリポジトリ全体のステージ済み・未ステージの変更を一覧にする。
  ステージ、ステージ解除、コミット、ローカルブランチの作成と切り替えができる。
- 変更をクリックすると差分を開く。ステージ済みは HEAD → index、それ以外は index → 作業ツリー。
  Git のパッチを行番号付きで表示し、バイナリと大きすぎるファイルは説明を表示する。
- フォルダを変えたとき、保存や Git 操作のあと、それ以外は3秒ごとに読み直す。
  読み取りが遅いリポジトリでは間隔を延ばす。UI スレッドでは Git を実行しない。
- 操作中の進捗は完了時に消す。「Switched to main」「Staged」などの成功通知をビューや履歴に残さない。
  結果はブランチ名と変更一覧に反映し、失敗時は Git のエラーを表示する。

## 実装

- `src/git/command.rs`: Git の起動を集約する。引数を直接渡し、シェル文字列を組み立てない。
  パスは literal pathspec として扱い、空白・改行・ワイルドカードを含む名前もそのまま渡す。
  ページャーと端末での入力待ちを無効にする。
- `src/git.rs`: `git status --porcelain=v2 -z --branch` の NUL 区切りの出力を読む。
  ステージ済みと未ステージの両方で変わったファイルは1件と数える。未追跡フォルダはまとめて表示し、
  保持する変更は各一覧2万件まで。サブモジュール内部の変更は走査しない。
- `src/git/diff.rs`: `git diff` の出力を表示用の行に変換する。パッチとして読める出力を得るため、
  外部 diff コマンドと textconv は使わない。
- `src/git/write.rs`: `git add`、`git reset`、`git commit` を専用ワーカーで順に実行する。
- `src/git/branch.rs`: `git for-each-ref` でブランチを読み、`git branch` と `git switch` で変更する。
  切り替え先で変わるファイルにエディタ内の未保存の変更があれば、先に保存か閉じることを求める。
  切り替え後は変更されたファイルのタブを読み直す。
- `src/git_ui.rs`: ワーカーへの依頼、古い結果の破棄、Git ビューとエクスプローラーへの反映を担当する。

## Git の設定

リポジトリ・ユーザー・システムの Git 設定を通常の Git と同じく使う。フック、署名、clean/smudge フィルタ、
Git LFS の処理と、index・参照のロックは Git に任せる。設定にこれらがあることを理由に操作を拒否しない。
マージ中のコミットなども Git が判断する。

状態の自動読み取りも Git の処理なので、フォルダを開いた際にフィルタや fsmonitor が実行される場合がある。
従来の「リポジトリ設定のコマンドを実行しない」という制限はなくなった。
バックグラウンドで index のロックを取り合わないよう、`GIT_OPTIONAL_LOCKS=0` を指定する。
ステージやコミットに必要なロックは通常どおり取得される。

## 検証

実際の一時リポジトリで、状態分類、差分、ステージと解除、コミット、フック・フィルタ、ブランチ操作、
未保存ファイルの保護、コミット前のブランチ、リンクされた worktree、競合、特殊なファイル名を確認する。
Git が PATH にない場合の無効化と、読み取りプロセスの中断もテストする。

```sh
nix develop --command cargo test --lib --bin kureha-code
```
