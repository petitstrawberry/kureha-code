# Source-to-Markdown scroll timing, 2026-11-09

Native macOS ARM64, release build, ScarletUI sgfx/wgpu backend. The symptom was
slow source-editor scrolling with a live Markdown preview visible; scrolling the
preview itself did not trigger the same workbench-wide layout.

## Measurement

- Before: Kureha `f49534c`, ScarletUI `88d8873`.
- After: the ordinary-preview-tab changes on `feature/independent-preview-panes`,
  with ScarletUI `34c2c080` and a bound ScrollView reveal target.
- Document: 150 headings and 150 paragraphs, 600 lines. Each paragraph reads
  `Paragraph with **bold** and some text.` No embedded images in this fixture.
- A disposable app process used the real macOS scene/event loop, with
  `SCARLET_UI_WINIT_RENDERER=sgfx` (CPU fallback disabled) and
  `SCARLET_UI_FRAME_LOG=1`.
- A temporary `on_idle` driver opened the Markdown preview beside the source,
  then advanced the source scroll binding by 35 logical pixels every 100 ms.
  Steps 11–39 produced 29 scroll updates; the process exited at step 55.
  The driver was removed after collecting the logs.
- The requested initial window size was 1100×760. macOS subsequently configured
  the measured window to **736×900 before, 720×900 after**, as recorded in the
  logs. These are close but not identical viewport sizes, so this is a diagnostic
  comparison, not a controlled same-size benchmark.
- Statistics use the final 29 `layout_us`/`frame_us` records in each log. Startup,
  initial layout, resizing and shader initialization were excluded.

| Warm source-scroll measurement | Before | After |
| --- | ---: | ---: |
| CPU update/layout, median | 40.435 ms | 0.049 ms |
| CPU update/layout, maximum | 48.483 ms | 0.144 ms |
| Frame work, median | 43.378 ms | 3.357 ms |
| Frame work, p95 (nearest rank) | 46.593 ms | 5.747 ms |
| Frame work, maximum | 51.374 ms | 9.934 ms |

`layout_us` measures the CPU dirty-tree flush. `frame_us` includes that flush and
backend preparation/submission. It is not display latency or a measured FPS.
The driver changes the source viewport programmatically; this is not an OS mouse
input replay. Mounted renderer regressions separately exercise wheel events,
scroll synchronization and retained layout.

The old source-to-preview path called `changed()` both to request a scroll and
to acknowledge it, rebuilding the workbench. The new path updates a bound reveal
range local to ScrollView; acknowledgement changes bookkeeping only. Unchanged
preview content keeps its layout and retained paint records. The idle regression
also verifies no presentation or Markdown layout across 30 unchanged cycles.
